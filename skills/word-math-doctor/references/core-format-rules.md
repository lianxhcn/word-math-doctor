# 核心格式规则

当用户的明确要求、期刊模板或文稿既有规范与本文件冲突时，优先执行前者，并在修改记录中说明。

## 1. 行内与独立公式

- 行内公式在原位置做最小替换，使用完整的 `m:oMath`，不得重写整段正文。
- 短导数、偏导数和比值通常采用横排形式，例如 `∂q/∂b>0`；不要仅为显示公式而抬高行距。
- 独立公式优先放在普通专用公式段落；公式与编号应保持原有关系。
- 不用点状引导符或大量空格定位编号。只有实际渲染无法稳定时，才可在用户授权下使用无边框表格，并记录原因。
- 长公式只在关系符、加减号、逗号或分号处进行可读的 OMML 分段；不得通过缩小字号、改变页面宽度或改写正文来掩盖换行。

## 2. 数学字体与样式

- 数学对象使用 Word 原生 OMML 与 Cambria Math；单字母变量通常为数学斜体。
- 多字符函数和标准运算符使用正体，例如 `exp`、`ln`、`max`、`min`、`arg max`、`BR`。
- 普通正文中的缩写，如 MPC、HtM、NHtM、KKT，保留正文格式；进入方程时再按数学语义决定正体结构。
- 代码字段和经验变量名在正文中保持正体；进入方程时以 OMML 正体文本表达，不能拆成若干斜体单字母。
- 中文说明、连接词和普通标点不得塞入 OMML；它们保留在原有正文 run 中。

## 3. 上下标、重音与定界符

- `B^*`、`b_i`、`b_{-i}`、`K_{k2}` 必须是实际 OMML 上下标结构。
- 多字符下标作为一个逻辑整体处理，不能依靠多个 run 的视觉拼接。
- 上划线、波浪线、花体、黑体、撇号、分式和矩阵使用对应的 OMML 原生结构；禁止 Unicode 组合字符与 OMML 重音混用。
- 绝对值、范数、集合括号、条件评价竖线和矩阵括号使用成对定界符结构，并实际检查伸缩后的渲染。

## 4. 中文、英文、数字与空格

- 中文语境保留中文全角标点；纯英文语境使用英文半角标点；公式内部保留数学半角符号。
- 中文与独立的英文、数字或行内公式之间按语义加入半角空格；公式与中文标点之间通常不留空格。
- 检查必须跨 Word run，不能只在单一文本节点中搜索。
- URL、DOI、代码、命令、文件路径和引用键不属于公式，除非用户明确要求修改。

## 5. 表格、编号与非目标格式

- 表格采用原位最小修改，不重建单元格、整行或整表；保存转换前后的文字、换行和数学对象快照。
- 保留列宽、行高、合并、边框、底纹和原有同行关系。发现一个单元格问题后，扫描整张表及同类表格。
- 已有成熟编号体系和正文交叉引用默认保留。只有用户明确授权时，才改用 `SEQ Equation`、`REF` 或其他重建方式。
- 公式转换可能导致行高和分页变化。不得为了维持页码而压缩字号或手工堆空格；应比较渲染结果并报告实质变化。

## 6. 批注、修订和高亮

- 默认保留批注、修订痕迹和高亮。批注返修模式下，只能删除已落实且通过验收的批注。
- 未解决、歧义或无法定位的批注必须保留，并进入待作者确认清单。
- 不把临时高亮当作永久完成标记，除非用户明确要求保留。
