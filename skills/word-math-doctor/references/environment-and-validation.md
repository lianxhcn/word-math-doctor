# 环境、渲染与重新保存

## 1. 能力分级

### 完整能力

可读取和写入 `.docx` 副本、检查 OOXML 与 OMML、逐页渲染，并通过 Microsoft Word 重新打开保存后再次审计。只有这种环境可以完成「全文数学公式规范化」。

### 部分能力

可读取 OOXML、运行扫描器和生成 checklist，但不能可靠渲染或重新保存。此时可以完成疑点扫描、作者裁定或有限的结构修复；交付中必须标注「未完成 Word 渲染/重新保存验收」。

### 不足能力

无法读取 Word 文档、无法验证输出中的 OMML，或只能把文档转换为图片/PDF。此时不得修改 `.docx`，只能说明所需的环境和授权。

## 2. 推荐工具边界

- Microsoft Word 是最终视觉与重新保存验收的首选。任何自动化都应基于输出副本，不能覆盖底稿。
- LibreOffice 或其他兼容工具可辅助预览，但不应作为未验证 OMML 的唯一权威重新保存器；若用其保存，必须与 Word 的重新打开结果分开记录。
- `python-docx` 适合读取常规内容，不应被单独当作复杂 OMML、批注、修订痕迹或原始排版的可靠转换器。涉及公式结构时，应直接检查 OOXML 或使用 Word 自动化。
- 随附 `scan_docx_math.py` 只读取 ZIP/OOXML 并输出 JSON；不修改原稿，也不判断某个表达式的数学含义。

## 3. 渲染和重新保存顺序

1. 对原稿建立 SHA-256 和结构快照。
2. 在新文件上执行经授权的修改。
3. 逐页渲染原稿与输出稿，优先比较修改页、复杂公式和参数表。
4. 用 Microsoft Word 重新打开输出稿并另存，再次运行结构扫描和渲染。
5. 若结构计数、OMML 片段、公式编号、行高、分页或字体出现异常，停止交付并列出异常。

## 4. 隐私与临时文件

- 不上传未公开文稿、批注、作者姓名、修订者信息或文档属性，除非用户明确授权。
- 忽略 Word 临时文件 `~$*.docx`。
- 将原稿、输出稿、渲染图和审计 JSON 放在可辨识的任务目录，不以临时文件替代最新底稿。
