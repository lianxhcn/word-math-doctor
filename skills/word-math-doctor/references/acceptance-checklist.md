# 验收清单与独立复核

清单项目应按所选工作模式使用。扫描模式不要求产生输出 `.docx`；全文规范化模式必须逐项完成或解释未完成原因。

## A. 结构

- [ ] 目标范围内需转换的数学表达式均为真正 OMML。
- [ ] 行内公式使用 `m:oMath`；独立公式使用 `m:oMathPara` 或专用公式段落。
- [ ] 正确的原有 OMML 未被无意义重建。
- [ ] 普通上标/下标、Unicode 伪数学和可见 LaTeX 已分类为转换、保留或非目标对象。
- [ ] 已有公式图片、MathType 或 OLE 对象均列出位置与处理决定；没有被静默忽略。

## B. 数学语义与样式

- [ ] 上下标、函数名、变量、花体、重音和定界符正确。
- [ ] OMML 内部正体/斜体正确。
- [ ] 公式与首次定义、正文解释和后续引用一致。
- [ ] 明显且唯一的修正已写入语义修正清单。
- [ ] 存在歧义的表达式没有被擅自修改。

## C. 非目标格式与表格

- [ ] 表格结构、列宽、行高、合并、边框和底纹没有未授权变化。
- [ ] 非数学文字、连接词、标点和原有同行关系完整。
- [ ] 标题、正文样式、图形、脚注、页眉页脚和修订痕迹没有未授权变化。
- [ ] 分页、行高或编号位置发生变化时，已在渲染对比中标明原因和影响。

## D. 字体、空格和技术字符串

- [ ] 数学对象使用 Cambria Math，中文与普通正文保持原有或用户指定字体。
- [ ] 中文全角标点、中英文/公式间空格和跨 run 边界符合文稿规范。
- [ ] URL、DOI、代码和文件路径没有被误改。

## E. 渲染与回归

- [ ] 全文逐页渲染无乱码、裁切、重叠或异常分页。
- [ ] 所有修改页和高风险公式已放大检查。
- [ ] 行内公式没有造成异常行距或字间距。
- [ ] 重新打开保存后，结构审计和渲染结果一致。
- [ ] 独立复核者或独立执行过程直接比较了原稿、输出稿、审计记录和渲染结果。

## F. 残余计数与诚实声明

最终报告列出下列数量及位置或保留原因：

- OMML 外数学候选对象；
- 普通上下标；
- Unicode 上下标和组合重音；
- 可见 LaTeX 候选；
- 公式图片与 OLE 对象；
- 未解决批注；
- 扫描器无法解析的 XML 部件。

任一残余项非零不必然阻止交付，但必须说明其类别和范围。只有目标范围内的残余项全部已解释、处理和验收后，才可声明全文规范化完成。
